# 项目记录：现行决定、教训、待验证与本轮工作区

本文件是项目的长期记忆，也是当前一轮工作的黑板（2026-11-14 建立，参照 vestra-player 的 `doc/process/rounds/history.md`）。流程规矩在 [AGENT_WORKFLOW.md](AGENT_WORKFLOW.md)。

## 1. 怎么用这个文件

- **改某个领域前先读 §2–§4**：现行决定不要推翻，死路不要再走，待验证的东西别当成已验证。
- **本轮工作区（§6）是黑板**：当前任务的简报、子代理报告要点、待用户裁决的问题都先记在那里。
- **一轮结束时折叠**：持久的决定写进 §2，教训写进 §3，没验证的写进 §4，搁置的写进 §5；然后清空 §6 的日志。细节留在 git 里（提交说明、旧版本的本文件），不在这里堆叙述。
- **一条一行**：日期 + 结论 + 出处（提交号或文档）。用户亲口定的标“（用户裁决）”。
- **子系统文档仍是唯一来源**：`docs/<FEATURE>.md` 写需求、设计和代码落点；本文件只放一行结论加链接，不复制内容。两边冲突时以子系统文档为准，并顺手修正本文件。
- 这是公开仓库：私有模块、实验性内容和用户个人信息不写进来，留在协调者的私有记忆里。

## 2. 现行决定

### 工作方式 / git

- 协调者 + 子代理工作流，实现交给后台子代理，主线留给讨论（2026-11-14，用户裁决）→ [AGENT_WORKFLOW.md](AGENT_WORKFLOW.md)。
- 只有协调者提交推送；不用 `git stash`、不强推、不改历史；提交只 `git add -A CombatSimulator Tests docs ':!CombatSimulator/Dev/Experimental'`。
- 对用户一律中文；界面指引写确切页签名和折叠栏标题，先在 `Gui/MainWindow.cs` 核对（2026-10-24，用户裁决）。

- 重写就删干净，旧路径不留作退路（2026-11-13，用户裁决）。
- 持久的决定和教训，在产生它的同一批工作里写进本文件（2026-11-14）。

### 战斗数值

- 一套数值：玩家、队友、敌人同威力同伤害，技能按自己 MP 池同比例扣蓝；强度档位只管血量（2026-11-13，用户裁决，`47f0a69`）→ [COMBAT_BUDGET_MODEL.md](COMBAT_BUDGET_MODEL.md)。
- 伤害按每秒威力计，装备/属性不参与；等级只按与玩家的差距，用“等级价值”曲线放大且不封顶（2026-11-11，`848bf39`、`ef0e0e8`）。
- 强度下拉默认 Auto（读 `BNpcBase.Rank`）；HP 倍率选项已删（2026-11-11，`697f2bb`）。
- 配方里的敌人也用同一组强度和等级，不再各自一套（2026-11-11，`83621e9`）。
- 队友也付 MP；被复活的人 50% HP、0 MP 回来（2026-11-13，`6e38892`、`3ac6147`）。
- 动作战斗是唯一战斗方式，旧的 tab-target 模式和 `ActionMode` 开关已退役；Fighting Mode 仍是独立实验模式（2026-11-13，用户裁决，`94b7f18`）。

- 招架成功才响“叮”声：按下时静音，成功时重放招架时间线让游戏自己再发一次（2026-06-20，`25e8840`、`62cd4a9`）。

### 崩溃分析

- 2026-07-09：dump 只能证明崩在哪，不能证明谁写坏的；骨架链表 `next=0xFFFF` 的崩溃其实是我们在渲染钩子里调 `NotifyTransformChanged` 造成的。
- 原生 AccessViolation 在 .NET 里 `catch {}` 抓不住，读游戏内存前必须先判空。
- 方法：Store 版 WinDbg 自带 `cdb`；先清空 `_NT_SYMBOL_PATH`；`-c` 用单行分号分隔；`.ecxr` 切到异常上下文；Dalamud 默认 minidump 不含堆，要读崩溃对象得改 full dump。CLR 崩溃日志的托管栈直接给出行号，比原生 dump 好用。
