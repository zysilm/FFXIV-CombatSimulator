# 自动死亡镜头（Death Shots）

状态（2026-11-22 夜）：自动死亡镜头**只在 Duel 相机模式下**运行；Directed 相机用自己的死亡构图（与 `4ac3039` 相同，见 §9.5）。**水平方向归玩家**：镜头不再选边，方位就是倒下那一刻相机所在的方位，之后只跟玩家的左右拖动走（§5）。程序只管注视点、仰角、距离（§4）。离线门槛全部通过；**这一版还没有在游戏里看过**（§11）。镜头好不好看只能在游戏里判断，离线指标是门槛，不是验收（见 §8）。

用户裁决：
- 2026-11-22：第一版只拍尸体；死亡镜头期间玩家保留左右环绕和滚轮（景别），俯仰锁定；默认一条连续镜头；无滚转；到地面以下做成选项（默认关）。
- 2026-11-22（更正）：**自动死亡镜头不得在 Directed 模式下起作用，只在 Duel 模式下起作用；Directed 的死亡构图必须原样恢复。**
- 2026-11-22（游戏内反馈）：只有 Low three-quarter 可用。永远不要硬切。身体被抓起时另给两个机位（Level / Slightly above）。
- 2026-11-22（游戏内反馈，路线 A）：侧向偏好“不太行”——倒下那一刻无法预知脸和身体最后朝哪边，自动选边只能是“先摆好、再纠正”，不流畅。**水平方向改为手动**：方位直接是玩家的，像游戏相机一样左右环绕，跟手；倒下时方位停在相机原来的位置，不自动转到正面，开始 / 静止 / 姿态变化时都不选边。选边的整套机制和 “Side preference” 下拉删除。只在方向上不同的三个档案删除。被抓时画面要从头到大腿中部，头顶上方不留大片空白。

## 2. 输入与输出

`DeathShotSolver.Begin(eye, lookAt, verticalFov)` 从当时的游戏相机开始；之后每帧 `Step(input)`：

- 输入：`Dt`；7 个点 `BodyPoints`（髋 `j_kosi`、胸 `j_sebo_c`、头 `j_kao`、肩 `j_sako_l/r`、脚 `j_asi_d_l/r`，世界坐标）；`Extra`（脊柱、颈、手臂、腿的其余点，拍全身时用）；`PhysicsStarted`；`PreviousSource`（切换那一帧同帧的骨骼）；`ExpectRagdoll`；`Profile`；`Aspect`；`BodyScale`（0 = 自己估）；**`UserYaw`（玩家从镜头开始起累计的左右环绕，弧度）**、`UserSize`（滚轮）；`AllowBelowGround`；`Grabbed` + `GrabbedFraming`。
- 输出：`Eye`、`LookAt`、`Fov`（**垂直视角，弧度**）、`Cut`；以及给日志和离线检查的：姿态类、实际档案、未阻尼的目标、去掉内置运动的位姿、是否静止 / 保持、**`Azimuth`（镜头所在的方位 = 起始相机的方位 + `UserYaw`，别无其他）**、`ShotChanged` / `ShotChanges`（档案变了：下拉、被抓、放下）、`Reason`（start / profile / grabbed / framing / released）、`PulledIn`、`TerrainPops`。

世界查询 `IDeathShotWorld`：`GroundBelow(from)`、`WaterBelow(from)`、`Blocked(from, to, out distance[, out normal])`。插件用 `BGCollisionModule` 的射线和 `TryFindWaterSurface` 回答；离线用录像里的地面回答。

## 3. 身体坐标系与姿态类

只用骨骼位置：

- 躯干轴 a = 胸 − 髋；横轴 s = 右肩 − 左肩（去掉沿 a 的分量）；正面 f = a × s。
- 长轴 = 脚中点 → 头的水平方向（水平跨度 > 0.35 m 才算有）。
- 体型 `scale` = （髋→胸 + 胸→头）/ 0.46 m。0.46 m 取自录像里用户自己的角色，使它的 Low close 落在 1.2 m（旧预设 1.0–1.35 m 的中间）。录像里 0.67–1.41。镜头的所有长度乘以它。
- 姿态类：直立按髋高分为 Standing / Kneeling；躺着按正面朝向分为 Supine / Prone / Side。带回差，一个类至少保持 0.75 s。**姿态类不再决定任何东西**（没有 Auto、没有侧向规则），只进日志和状态行。

## 4. 档案

三个，只按**主体、距离、高度**区分；方向不是档案的一部分。都是绕主体的自由环绕（方位归玩家，仰角和距离归档案）；长度为参考体型的值；仰角为眼位相对注视点（负 = 在下方仰拍）。窄镜头（FoV 0.60–0.62）；身体静止后慢慢推近（8 s 内靠近 12%）。尸体在地上时眼位到不了地下，自动变成贴地平拍（“Allow below ground” 开着时保持仰拍，§9.6）。

## 5. 每帧的顺序

1. **身体**：位置源切换的处理（见 §6）→ 髋下的地面（平滑 0.2 s）→ 平滑后的身体坐标系（0.1 s）→ 姿态类 → 是否静止（7 个点都 < 5 cm/s 持续 0.8 s；静止后任一点离开停下的位置 > 0.25 m 才算又动了）。等布娃娃期间不算静止。
2. **保持**：身体静止后，镜头按停下那一刻的点求解并冻结，内置运动（推近）开始；又动了就恢复跟拍，推近的偏移用弹簧收回。
3. **档案**：没被抓 → 下拉里的档案；被抓 → 被抓机位（§6.1）。档案变了（下拉、被抓、放下）只换主体 / 仰角 / 距离的目标，由阻尼缓过去。**这里没有任何选边**。
4. **方位**：`方位 = 起始相机的方位 + UserYaw`，逐帧直接赋值——没有弹簧、没有限速、没有程序自己的成分。起始相机的方位 = `Begin` 给的眼位绕注视点的方位（正上 / 正下方没有方位时取身体正面）。
5. **距离**（闭式）：视线方向固定时，每个点要求沿视轴至少后退 (|x| + r) / (safe · tan 半视角) − z，取最大的那个，再与档案的最小 / 最大距离比较，乘以滚轮。
6. **约束**：眼位 ≥ 地面 + 0.10 m、≥ 水面 + 0.10 m；被地面挡住时仰角让路并重新求距离。**视线被挡不改方位**——主体中心 → 眼位的射线被挡时，眼位沿同一条线收到挡点前 0.15 m，FoV 放宽以保持大小（上限 1.35 倍）；挡的东西没了再缓回去。
   - 墙（挡面法线不朝上，或世界不给法线）：收到多近都行，最近到 0.45 m × 体型。
   - 地面的起伏（挡面法线朝上 45° 内；低机位贴地时视线是擦着地面过去的）：最多收到原距离的 60%；起伏离主体比这还近就不动（不往一个土包上凑）。
7. **阻尼**：相机表示为注视点 + 眼位绕它的轨道（方位、仰角、距离）。注视点弹簧 0.30 s、限速 3 m/s；仰角、距离弹簧 0.60 s，仰角 ≤ 35°/s、距离 ≤ 2 m/s；FoV ≤ 0.5 rad/s。目标离开 3 cm 才响应（死区；身体静止后死区关闭，精确对准）。进入的前 2.5 s 用更慢的弹簧（注视点 0.60 s、轨道 1.0 s）：**进入时只有仰角、距离、注视点在动**。开始和每次换档案后，限速在 0.6 s 内线性放开。
   - 收近（被挡）用 0.2 s 的弹簧（墙在画面里的时间要短），放出去用正常的。
   - 玩家正在转（以及停手后 0.5 s 内）距离用 0.15 s 的弹簧：全身横着看比顺着看需要更远，转的时候距离要跟得上，否则身体被画面边缘切掉。这是玩家自己的动作带出来的变化。
8. **出手**：眼位每帧最多走 3 m/s、视线转速最多 60°/s——**这两个上限只管程序自己的动作**：先把上一帧的眼位和视线按这一帧玩家转过的角度绕注视点带过去，再套上限，所以玩家转多快镜头就转多快。接近地面的几厘米内软着陆；前方地面高于一帧能爬的高度时眼位先原地上升再前进。若发现眼位已在地形里面，放到表面上并记为一次硬切（`TerrainPops`）。`Output.Cut` 只剩两种：没有起始相机的第一帧，和这一种。

### 5.1 记住的角度（2026-11-22 夜，用户要求）

用户：死后调好了角度，新一场开始时相机复位，下一次死亡镜头就固定在那个复位的方向上；应该记住上一次死亡的水平角度，死亡时平滑转过去；“在重置时记录”。

- **存什么**：镜头方位**相对死亡时的朝向**的角度（`镜头方位 − 角色根的 yaw`，弧度），设置 `DuelDeathShotAngle`（`float?`，空 = 没记过），随配置保存、跨会话。死亡动画是相对朝向播放的，同样的相对角度下次给出同样的画面（用户旧 Death Cam 预设就是这样存的）。“死亡时的朝向”= 这次死亡的镜头第一次开始那一帧角色根的 `Rotation`。
- **只存一个值**，不为被抓状态另存：被抓时身体被抓它的怪转到哪儿是每次不同的，那时转的角度是针对那一刻的姿势，下次重现不了。所以**被抓期间玩家转的角度不计入**（`grabYaw`，从存的值里减掉），存的是躺地镜头的角度。
- **什么时候存**（`DeathShotDirector.RememberAngle`，在每个 `Stop` 的最开头调用，早于释放相机和任何复位；用的是镜头运行时每帧更新好的值，所以镜头当时在等待 / 已停也能存）：
  - 存：`simulation reset`（重置 / 重新开始一场）、`no simulation`（停止模拟）、`revived`（复活，含镜头已让给游戏过场时的复活）、`not in Duel mode`（换了相机模式）、`a scene has the camera`（私有场景接管）、`no longer wanted`、`unloaded`（插件卸载）。
  - 不存并丢弃这次死亡的角度（画面可能是坏的）：`zone change`、`logged out`、`error`、`tick stalled`、`the body cannot be read`、`no player`。
  - 暂不存、保留这次死亡的角度：游戏自己的过场 / GPose 接管相机（镜头回来时回到原角度，之后正常结束时再存）。
  - 条件：这次死亡里玩家确实转过相机（躺地时累计 > 2°），或者用的就是记住的角度。没转过、也没有记住的值 → 不存（否则“相机恰好在哪儿”会被当成玩家的选择）。
- **死亡时**（`DeathShotSolver.Begin(…, rememberedAzimuth)`，= 朝向 + 记住的角度）：方位从相机当前的方位沿**较短的弧**转过去，smoothstep（起止速度为零），时长 1.2 s；转角大到峰值会超过 150°/s 时延长（180° 用 1.8 s）。与高度 / 距离的进入缓动同时进行。没有记住的角度 → 与之前逐位相同（留在相机原来的方位）。
- **转的过程中玩家拖动**：**取消剩下的转动**，停在当时的位置，从那一刻起方位只跟手（累计拖动超过 1° 才算，手抖不算）。不选“继续转完 + 叠加手的增量”：那样相机在玩家拖的同时还在自己动，手感是在打架，而且玩家已经在自己摆了。取消后镜头结束时存的就是玩家最后摆的角度。
- 同一次死亡里镜头重新开始（过场镜头交还后）：转回这次死亡镜头原来的角度。
- 界面：Duel Camera 折叠栏最下面一个小按钮 **Forget angle**，只在有记住的角度时出现；按了之后下次死亡镜头留在相机原来的方位。没有它就没有办法回到“不记”的状态。
- 日志：`DeathShot: start — … (remembered angle +N° from the facing F°; easing +M° to azimuth A°)`；结束时 `DeathShot: remembered +N° from the facing at death (<原因>; was …)`，或 `no angle remembered (<原因>) — the camera was not turned during the shot`。
- 离线：“Close recall” 列（记住的角度 = 朝向 + 140°）：568 次死亡结束时方位与目标相差 ≤ 0.00003°，转角 0–180°（中位 90°），1.22–1.89 s 转完，最快 150°/s，硬切 0；转的那段视线最快 163°/s（这是程序自己的转动，不受 60°/s 限制，只报告）；主体在画面内 98.2%（转的过程中相机还在 5 m 外）；760 次里有 2 帧眼位在地形内被放到表面。门槛“没有输入就没有方位变化”改为“……除非正在转向记住的角度”。单元检查 6 项：转到目标（140°，1.42 s，峰值 150°/s，起步 3.5°/s）；跨 ±180° 走短弧（20° 而不是 340°），179° 用更长时间；转的过程中拖动 → 停在当时（140° 里的 43°），之后逐帧只跟手；手动不到 1° 不取消；没有记住的 → 逐位相同；同一相对角度在朝向不同的身体上给出同样的画面。没有记住的角度时全部 2280 次运行与 `b2f76d7` 逐位相同（`hash --against`）。

## 6. 布娃娃

- 动画期间注视点跟着主体走（镜头跟着倒下），方位不变。
- 物理开始时位置源从骨骼原点变成刚体中心，两者差 1–24 cm。求解器在切换那一帧记下每个点“旧源 − 新源”的差，0.5 s 内淡出，并在这 0.5 s 内把阻尼平滑地加倍再放回。旧源的值：调用方给了 `PreviousSource` 就用它，否则假定每个点按上一帧的速度继续走。
- 静止 → 保持并开始推近；又被移动 > 0.25 m → 恢复跟拍。**静止时不重新摆位**：身体最后朝哪边都不动方位。

### 6.1 被抓起（“When grabbed”）

- 信号：`EnemyControlController.IsHoldingGrab`。求解器输入 `DeathShotInput.Grabbed` + `GrabbedFraming`。
- 两个机位（设置 `DuelDeathShotGrabbed`，默认 Level）。**主体：头顶到大腿中部**（`ShotSubject.HeadToThigh`）：
  - 上端 = 头顶（`j_kao` 沿颈向外 18 cm），下端 = 两条大腿中点的平均（髋朝各自的脚 0.30 m × 体型，腿蜷着不够长时取到脚的一半）。
  - **注视点 = 上下两端的中点**（挂着的身体上在胸和髋之间，约下胸 / 腹部；参考体型上在髋上方 0.17 m，胸在 0.24 m）。
  - **距离按这段范围贴合**（安全框 0.86，FoV 0.62）：上下两端各留同样的边，所以头顶上方只有正常的头部空间，没有大片空白。静止挂着的参考体型：头顶在画面高度的 91.2%（头部空间 8.8%），大腿中部在 8.8%，距离 1.78 m（Slightly above：头顶 91.1%、大腿中部 14.6%、1.84 m）。以前是胸到头、画面高 0.95 m、1.40 m。
  - **Level**：仰角 0°。**Slightly above**：仰角 +17°。这两个不属于低机位，“Allow below ground” 对它们无效。
- **方位仍是玩家的**：抓住、摆动、放下都不改方位。
- 更稳：被抓期间注视点弹簧放慢到 4 倍（1.2 s）、轨道弹簧 2 倍、注视点死区从 3 cm 放宽到 12 cm（都在 0.5 s 内渐变进出）。合成的摆动身体上（±20° / 0.5 Hz 摆 + ±30° / 0.3 Hz 扭）：7 s 里胸走了 3.13 m，眼位只走了 0.46 m；头顶、胸、髋 100% 的帧在画面内，头部空间随摆动在 5.1–10.7% 之间；因为相机比身体稳，摆到两端时画面下沿会略高于大腿中部（Level 最多超出半幅画面的 2%，Slightly above 12%）。
- 放下：松手后仍用被抓机位跟着身体落地，等它静止（或 4 s 后）再缓回下拉里的档案（只变主体、仰角、距离）。

## 7. 与设计稿的出入（实现时定的）

- 眼位的阻尼作用在**轨道坐标**上，不是直角坐标上的眼位弹簧。
- 进入不是固定 2.5 s 的混合，而是“前 2.5 s 用慢弹簧 + 限速”。
- Kneeling 不设髋高下限。
- Low close 的画面高取 0.80 m，这样 FoV 0.62 时距离正好是旧预设的 1.25 m。
- 体型按脊柱长度估，参考值取用户自己的角色（§3）。
- 软着陆使贴地时眼位比净空高 5.5 cm（约离地 0.155 m）。

### 8.4 离线能证明和不能证明的

能证明（在这 95 条轨迹上）：主体留在画面里；眼位不进地面；程序自己的动作有速度上限且没有跳变；**没有输入时方位不变**；身体静止后镜头不漂；位置源切换不产生跳变；每个档案的仰角和距离。

不能证明：
- **好不好看、跟不跟手**。手感只能在游戏里试；离线只证明方位与输入逐帧相等。
- **真实的遮挡**：录像里只有地面。墙的收近只在合成的墙上测过。
- **游戏里 `DirH` 的行为**：离线喂的是累计角度；游戏里它来自游戏相机自己的 yaw 的逐帧变化（§9.2）。如果游戏在死亡期间自己动 yaw（目前没见过），镜头会跟着漂。
- **被抓**：只在合成的摆动身体上测过。
- **体型**：只见过 0.67–1.41 倍。

### 9.1 什么时候跑

- **只在 Duel 模式**：Camera 页签的 **Camera mode** = **Duel**、模拟在进行、没有私有场景占用相机、玩家已倒下 → `DeathShotDirector.Tick` 每帧求解。Directed 模式下它什么都不做。
- 结束：复活（0.3 s 过渡回游戏相机，位姿和 FoV 一起插值）；重置 / 停止模拟 / 换图 / 登出 / 卸载 / 离开 Duel 模式 / 私有场景开始（立即）；游戏自己的过场或 GPose 开始；`Tick` 超过 0.5 s 没跑（`tick stalled`）；连续 120 帧读不到身体。
- 开始不了时每种原因每次死亡记一行 `DeathShot: cannot start yet — <原因>`，并继续每帧重试。
- 过场跟拍镜头（owner 60）优先：它占着相机时自动死亡镜头等待；它开始淡出的同一帧（`CutsceneShotDirector.HandingBack` → `ResumeNow`）自动死亡镜头从它留下的画面重新开始——**方位也从它留下的画面取**，玩家的累计环绕归零。
- 所有者 `CameraOwner.DynamicDeath`（25）。位姿交接三级：决斗镜头先写，自动死亡镜头覆盖它，过场镜头覆盖两者。

### 9.2 每帧

1. **位置**：22 根骨骼（前 7 根是身体坐标系，其余供全身档案）。布娃娃 `IsActive && PhysicsStarted` 且 7 个点的刚体都读得到时改用 `Ragdoll.GetBodyWorldPosition`。切换那一帧把同帧骨骼作为 `PreviousSource` 传入。
2. **`ExpectRagdoll`**、**`BodyScale`**：同前。
3. **被抓**：`Grabbed = EnemyControl.IsHoldingGrab`，`GrabbedFraming = DuelDeathShotGrabbed`。
4. **世界**（`CameraCollisionWorld`）：地面两条射线；水面；遮挡一条射线并带回挡面法线。每帧射线数在 5 s 汇总里。
5. **玩家的手**：**左右环绕 = 游戏相机自己的 `DirH` 的逐帧变化量，累加成 `UserYaw`**（一帧 > 1 rad 的丢弃）。死亡镜头占着相机时没有人写 `DirH`（它只提交 FoV、保持的缩放和俯仰），所以 `DirH` 的变化就是玩家的鼠标 / 右摇杆，带着游戏自己的灵敏度和反转设置——手感与游戏相机一样，没有输入就没有变化。滚轮每格约 10% 成 `UserSize`（0.5–3）；俯仰不读（锁定）。游戏自己的缩放距离和俯仰在镜头期间保持在开始时的值。
6. **交接**：眼位 + 注视点走 `ActiveCameraController.PoseOverride`，FoV 走协调者。求解器输出原样写入。
7. **时序**：求解在框架帧里做，位置比画面晚一帧。

### 9.6 “Allow below ground”（默认关）

背景：用户仅存的三个旧 Death Cam 镜头眼位在髋下 0.27–0.48 m，当时关着相机碰撞——尸体躺地后镜头在地面以下，透过单面的地面往上拍。

- 作用范围：下拉里的三个档案（都是低机位）。被抓的两个机位不受影响。
- 开启后：仰角不给地面让路，眼位不抬到地面 / 水面以上，没有软着陆和“眼位在地形内”；只保留眼位 3 m/s 限速。地面不算遮挡，墙照算（挡面法线朝上 ≤ 45° 且挡点在尸体地面 ±0.5 m 内才算地面）。
- 从地下回到地上（换到被抓机位、关掉选项）：眼位以 ≤ 3 m/s 穿过地面升上来，不切。
- 离线（Close bg 列）：躺地静止时仰 22°、1.25 m，深度中位 0.40 m。

## 10. 私有模块

自动死亡镜头没有私有模块的入口：私有场景占用相机时它不跑（`sceneActive`）。`DynamicCameraController` 上的各个覆盖项都作用在 Directed 相机自己的死亡构图上，含义与 `4ac3039` 相同。

## 11. 游戏里看什么

前提：Camera 页签 → **Camera mode** 选 **Duel**；折叠栏 **Duel Camera** → **Duel death shot** 选档案。Camera 页签 → 折叠栏 **Cutscene Shots** 里的 Death 留空，才是纯自动镜头。

0. **记住的角度**（§5.1）：第一次死亡时把镜头转到喜欢的一侧 → 重置 / 开新一场（日志 `DeathShot: remembered +N° from the facing at death (simulation reset; …)`）→ 下一次死亡，镜头在 1–2 s 内平滑转到同一侧（`start — … remembered angle +N° …; easing +M°`），画面应与上次相同（相对你倒下时的朝向）。转的过程中拖动：立即停止自动转动、跟手。没转过相机的死亡不改变记住的角度。Forget angle 按钮按了之后下一次留在相机原位。重启游戏后仍记得。
1. **倒下的那一刻镜头不绕**（没有记住的角度时）：相机留在原来的方位，只是降低、靠近、对准身体（约 2–3 s）。日志 `DeathShot: start — … azimuth N° (kept …)`。
2. **左右拖动**（鼠标 / 右摇杆）：镜头绕着身体转，跟手，像游戏相机；松手就停在那儿，之后身体怎么翻、布娃娃开始、静止，镜头都不自己转。5 s 汇总里 `player's orbit +N° since the start`——不动手时这个数不变。**如果不动手它也在变，说明游戏自己在动相机的 yaw，请把那几行日志给我。**
3. 上下拖动没有反应（锁定）；滚轮改远近。
4. 三个档案：Low close（髋到胸，近）、Low on the face（头，近）、Low full body（全身，远）；死亡中在下拉里换，相机缓过去，方位不变。
5. 靠墙：把镜头转到墙后面，镜头沿原来的方向收近到墙前、视角变宽（日志 `view blocked … pulled in front of it`），转开后缓回去（`view clear again`）。不会自己跳到另一侧。
6. 被抓起：日志 `the body is held`，画面从头顶到大腿中部，头顶上方只有一点空间；Level 平视 / Slightly above 略俯；左右仍然归你。放下并静止后缓回原档案。
7. Allow below ground：勾上后躺地的三个档案到地面以下仰拍（5 s 汇总里 `eye … m BELOW ground`）。
8. `camera check over 60 frames`：眼位 / 注视点差毫米级，镜头差 < 1°。布娃娃开始那一帧画面不跳；过场死亡镜头结束后 `DeathShot: resumes`；复活 0.3 s 回到决斗镜头。
9. **Directed 模式**：死亡时是原来的构图，日志里没有 `DeathShot:` 行。

## 12. 已知的不足

- 位置比画面晚一帧。
- 记住的角度是相对角色根在倒下那一帧的朝向；如果某个死亡动画（模组）开头会转身，同样的角度看到的就不一样。转向记住的角度最快 150°/s，开始时相机还远，画面扫得快。
- 没有记住的角度时，倒下时相机在哪个方位就从哪个方位拍：如果当时在背后，看到的就是背面，要自己转过去。这是这一版的取舍（用户决定）。
- 眼位被地形拖住时（尸体掉下坎、眼位要先沿地面绕过去），渲染出的方位会暂时偏离几度到几十度，追上后回到原方位。
- Low full body 顺着身体看时近端容易贴边；推近量在那种情况下减半或取消。
- 墙离主体不到 0.45 m × 体型时，收近的眼位在墙后面（再近就进到身体里了）。地面起伏挡住视线而离主体很近时不收近。
- 遮挡只查地形和墙，不查角色；被抓时抓它的那只怪可能挡在镜头前。
- 被抓时相机比身体稳，摆幅大时画面下沿会在大腿中部上下浮动。
- 被抓信号只有 Enemy Control 的抓取；私有模块自己的抓取不算。
- 凶手双人构图在 Duel 的自动死亡镜头里没有（Directed 的死亡构图里有）。
